## Source review

The first-attempt caller is correctly visible:

`cli._cmd_commit` → `cli_native.commit_document` →
`_preview_detached_document` → authenticated `TimelineSession.open` →
`Timeline(...).commit(...)`. It verifies the detached document's project,
timeline, and exact `base_parent.revision_id`/`publication_id` pair, then the
existing G2 session/G3 emitter builds the Runtime request. The first-attempt
path therefore preserves the existing `api_version`, scope, exact base pair,
commands, label, steps/patch/reads, atomic merge, source, dry-run and receipt
machinery generated by `Timeline.commit`.

Two blockers prevent crediting the complete requirement:

1. **Durable retry bypasses Runtime idempotency and authentication.** At
   `astrid/packs/timeline/cli_native.py:111-161`, `_replay_document_commit`
   scans only one `history(..., limit=200)` page and, when it finds the key,
   returns the stored receipt locally. `commit_document` takes that branch at
   lines 173-176, before opening/submitting through `TimelineSession` or
   `Timeline.commit`. C0 §1 requires Runtime to authorize an exact retry and
   return the durable `{data, receipt}` winner without re-execution. This draft
   neither exercises that Runtime replay nor paginates history; after more than
   200 entries it falls back to recapturing/fetching the old closure, which can
   fail before Runtime gets the exact key. The six new tests only prove a local
   in-memory history lookup (`DetachedRealm`/`DetachedPort`), not a real
   Runtime HTTP idempotency retry.

2. **Empty idempotency keys are accepted before any write guard.** The parser
   marks `--idempotency-key` as required, but does not reject `""`; the handler
   validates only the message (`cli_native.py:164-171`). An empty key reaches
   `Timeline.commit` (`cli_native.py:105-108`) and can create the detached
   `.outbox.json` flight before the transport rejects it. C0 requires a key for
   mutations, and the requested empty-input/no-write negative is not covered.

Additionally, `_preview_detached_document` explicitly passes
`parsed.file.with_suffix(".outbox.json")` (`cli_native.py:88-91`), contradicting
the handler docstring's claim that it makes no local sidecar/cache writes. The
missing-file and `/dev/null` malformed-input probes did not create a sidecar,
but a valid first attempt does create this local outbox; this should be resolved
alongside the retry design if no-write means no local mutation.
