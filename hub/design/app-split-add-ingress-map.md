## Multi-split: sequential planning inside one atomic intent

The old batch helper makes one full-config installation. Keep this atomicity requirement. The native port at 2f945 supports only one command/one preview operation; the staged session test that splits a newly created right half proves a dependent suffix, **not** one atomic multi-split gesture.

Each native split records `parent/collection:clip` container-shape read and `collection.clips` selection (`members`, `order`, `boundaries` = whole current collection, `policy:'guard-membership'`), plus `collection.clips.after` with whole order and target/next boundary. It also reads every other member's relationship/transition leaves. Splitting A creates A-right and changes the collection; B captured independently from the original bundle is stale even if its target row is otherwise untouched. Rewriting B's selection arrays afterward does not certify B's other new-member reads/bindings/derived writes.

Required separate batch task: freeze ordered valid input IDs, original playhead, eligibility and all caller-reserved right IDs once. Determine the original intersecting/interior targets using current behavior. On an isolated original bundle, capture/execute split 1, then capture split 2 on the resulting bundle, and so on. Retain each original resulting command/claims and the final bundle; nothing touches live display/session until every member validates. Finish replays the stored sequence against the current raw bundle with local-generation fencing; never recapture to repair guards after an ACK or remote edit. Submit **one** payload with ordered `commands[]`, one outbox intent, one commit request/publication and one undo unit. Runtime must accept/refuse the whole batch.

Preview support must likewise compose each full-row native preview into a temporary TimelineData and install only the final result once. Current single-operation projector intentionally rejects multiple operations; batch needs explicit validated batch dispatch/recovery, not `forEach(submit)` or N calls to live `commitData`. Preserve no-op clips outside the playhead and reject an unsupported member without a partial split of eligible members. Test second-member refusal and concurrent membership reorder/insertion, restart recovery, exact retry and one guarded undo. Until this exists, do not describe multi-split as migrated or remove its positive UI expectations.
