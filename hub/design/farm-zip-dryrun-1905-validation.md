## C. Erasure exposure (the important finding)

| Repo | Upstream commits not in integration tip | Upstream-only files since merge-base | Patch files | Patch files that are also upstream-only | Upstream base an ancestor of tip? |
|---|---|---|---|---|---|
| agent | 22 | 98 | 977 (43 deleted) | 98 of 98 | no |

| app | 68 | 154 | 701 (42 deleted) | 154 of 154 | no |
| composition | 0 | 0 | 118 (2 deleted) | 0 | yes |

Meaning: the squash patch is base→integration. Where integration lacks upstream commits, the patch carries their undoing. Every upstream-only file appears in the patch, so applying the patch to current main overwrites or reverts that upstream work. `git apply --check` passes, because the patch's preimage is current main. This is the silent new-main-to-old-tree deletion the brief asked me to rule out. I have not split the reverts from overwrites, and I have not resolved it.

Recommendation: do not package these patches. The integration branches need to merge forward from current upstream main first, so that upstream main is an ancestor of the tip. Then the base→integration squash is a real forward delta. This is an orchestrator decision.
