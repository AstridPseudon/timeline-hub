## agt-m1-readback — published readback compatibility seam (2026-10-19)

The Agent read adapter consumes the frozen Runtime history shape when the generated client exposes
`list_timeline_commits(project_id, timeline_id, cursor, limit)`: each accepted history item keeps its
`publication_id` and `previous` head pair even when multiple items point at the same immutable
`revision_id`. Positional refs follow publication ancestry; an explicit revision-id prefix resolves
the immutable revision without collapsing the history rows used by undo. The existing
`open_composition` parent-link walk remains a compatibility fallback for older Runtime clients and
fails closed when ancestry is unavailable.

`timelines show --published --revision-id REV` never consults a local draft and labels the revision
actually present in the loaded immutable bundle (`base_parent.revision_id`), not a moving head or an
unverified requested label. A missing exact read remains the Runtime error. The accepted-result
consumer may therefore print `timelines show TL --project PROJECT --published --revision-id REV`;
publication/receipt identity remains available from commit/history data and is not invented in the
show bundle.
