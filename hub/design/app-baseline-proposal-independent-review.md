The credentials change follows directly from the identical predicate in [mediaFetchCredentials](/tmp/claude-0/-home-user-repo/7dc61be1-7066-52e0-a5d0-94f90e61430a/scratchpad/orch/workers/app-m4-baseline-proposal-independent-review/notes/proposed/src/shared/lib/media/mediaCrossOrigin.ts:19); that test stops at its first CORS assertion, so the second assertion is not separately reported as executed for this failing row. Existing [connection tests](/home/user/work/wt/app-m4-baseline-proposal-independent-review/src/integrations/runtime/connection.test.ts:81) similarly do not cover a blob with the configured door origin.

This is a demonstrated helper/source-contract change, **not evidence of a browser media failure, a reachable producer emitting this URL, or an authorization bypass**. In a normal hosted page, newly created blobs carry the hosted page's origin and retain their behavior. Nevertheless, the exact patch does not satisfy this brief's unrestricted blob-preservation condition. Recommended correction for a subsequent authorized proposal: restrict the newly added gateway arm to actual HTTP(S) transport URLs while retaining the existing configured-origin helper and the unchanged canonical managed predicate. Do not broaden canonical object recognition or alter original behavior tests to bless this exception. No correction was implemented here.
