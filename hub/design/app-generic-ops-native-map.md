# App M2 generic operations → native consumer cut

Status: design/source audit only. Audited App `32068aa728d29db2fe5635e52b15ac0f9db6515e` (the `tl/app-m2-native-ui-qualified-source` base), with the settled M2 priority-1 rules in `PLAN.md` and `design/app-writers.md`. This is a consumer plan, not a claim that the native pair, popup media contract, or opaque-root writer closure is integrated.

## Result

The smallest useful native consumer is a single `TimelineOps` patch-batch adapter owned by the command session. It must classify and capture the complete patch before submitting anything, execute every supported native command against one original authored bundle, and enqueue one command intent containing all commands and one combined local preview. It must refuse the complete patch when any operation is unsupported. It must not call `commitData(nextData, { save: true })` for a native-capable patch, and it must never use the generic compiler's normalized `nextData` as the durable or local authored result.

This is a central batch seam, not a collection of per-operation calls to the existing ports. The current ports each enqueue one intent; calling them one after another would make a generic mixed apply non-atomic. The session's existing `Payload.commands` array and commit request already carry an ordered command list, so the smallest extension is a batch capture/finish/submit port that feeds that existing queue.

## Actual current reachability

* `hooks/useTimelineOps.ts:226-307` checks editability, checks the live base version, validates the whole patch, compiles it, special-cases one parent track-label update through `trackLabelPort`, and sends every other valid patch to `commitData(compiled.nextData, { save: true, semantic: true })`. Thus the current generic path is still a snapshot writer. `preview()` at `:172-222` uses the generic compiler and `flush()` at `:449-457` only waits for the host save barrier.
* `hooks/useTimelineState.ts:780-800` wires only `trackLabelPort` into `useTimelineOps`; the command session's move, delete, trim, track-create, scalar, PARAM, and parent-add ports are exposed separately at `useTimelineCommandSession.ts:285-293` and are used by gesture/public-command code, not by generic apply.
* `hooks/useTimelineCommandSession.ts:134-150` projects previews locally with a native projector where one exists, then `commitData(..., { save: false, skipHistory: true })`. `commands/commitSession.ts:231-247` persists one payload to the outbox, and its request builder sends the ordered `commands` array. The existing individual ports (`:259-700`) preserve capture basis and enqueue independently.
* `lib/proposal-runtime.ts:560-566` does the correct stale-before-mutation check and then calls `timelineOps.apply`; it does not have a second writer. `runtime/extensionContextFactory.ts:172-218` only scopes and delegates the same adapter. A supported proposal therefore becomes native automatically after the adapter change; an unsupported proposal must remain pending and receive the complete unsupported diagnostic.
* `lib/source-map-runtime.ts:151-191` emits `project-data.write/delete` through generic apply. Those families have no native port and remain unconverted.
* `lib/compiler-canary.ts:432-442` applies source-map data first, then builds/applies a second main patch. That is a reachable two-apply writer and cannot be admitted to the native cut while it contains project-data operations. It must remain an explicitly unconverted ingress (or later build one complete supported patch); it must not be made native by submitting the two parts independently.
* `runtime/element-adapter.ts:487-523` reads a document and calls `ElementTimelineRoutes.save`, which calls `saveTimelineAtHead` (or the numeric `saveTimeline` fallback) exactly once. This is a separate direct CAS writer, not a `TimelineOps` caller. Existing element operations change `elementRef`, `params`, fades, transitions, or create an overlay with a locally generated ID. No existing native port provides the complete element contract, explicit created-ID binding, or element graph semantics. Keep it outside this cut; do not route it through a generic snapshot fallback.
* `hooks/useTimelineCommandsService.ts` still uses `applyValidatedMutation` for ordinary `addClip`, `updateClip`, `trimClip`, `splitClip`, `addTrack`, and `moveTrack`, while `moveClip`, parent `deleteClip`, and `setClipParams` have native-adjacent paths in the same file/session. The public facade needs the same bounded native classification; it must not silently continue to snapshot-save a covered shape after the cut.

Preview, `commitData(save:false)` projection, outbox persistence, ACK/retry, and Runtime undo are separate concerns. A native apply may update the local display through the native preview callback before ACK, but only the command request creates accepted history.

## Exact native reuse matrix

The following is the proposed first consumer set. “Supported” means the whole operation can be captured losslessly from the original raw basis. It does not mean every shape accepted by the broad public `TimelinePatch` validator is supported.

| Generic family | Native mapping and exact accepted shape | Scope / refusal boundary |
|---|---|---|
| `clip.move` | Existing `ClipMoveCapturePort` → `clip.move`. One operation, finite non-negative absolute `payload.at`; no `before`, `after`, `order`, or cross-track `payload.track`. The port resolves parent or explicitly projected occurrence raw identity and emits the native `on` value plus quantized preview. | Parent and occurrence are supported when the raw identity/owner binding is unambiguous. Relative anchors, free multi-move, group moves, and a `track` different from the captured track are refused as one patch. No display ID/prefix inference. |
| `track.update` label | Existing `trackLabelPort` → `track.set`. Exactly one merge-mode label-only update with a string `payload.label`; no clear, muted, kind, role, app, or child track. | Parent track only. The current session refuses a child track (`hasChildTrack`) and ambiguous ownership. Occurrence labels are not a native path. A batch containing label plus any unsupported operation is refused in full. |
| `clip.update` scalar | Existing `clipScalarPort` → `clip.set`. Values may contain only `hold`; `clear` may contain distinct `hold`, `asset`, and/or `transition`, with the existing native rules. No `mode`, no other values, and no simultaneous set+clear of one leaf. | Parent or occurrence clip through `resolveOwnedClipRef`. Occurrence requires the native translation-only, FPS, extent, blocker, source/media, and ownership checks. `hold` clear needs an explicit surviving source window. `asset` clear refuses alternate media selectors. Opacity, position, effects, volume, transition set, source windows, time maps, and arbitrary scalar leaves remain unsupported. |
| `clip.update` built-in PARAM | Existing `clipParamsPort` → `clip.set-params`. The accepted generic projection shape is one `clip.update` whose payload has a JSON object at `params`; map its own keys to native `values`, with no generic params-clear encoding. Preserve null, empty, absent, empty-key, false, zero, list order, and own keys exactly in the native args. | Parent or occurrence clips with an explicit raw owner. Native built-in schema validation is authoritative. A selected project-pack element whose values change is refused unless the native verified schema/source inputs are already present; generic patch metadata cannot fabricate those pins. `params: null`, non-object params, and a generic attempt to clear PARAM leaves are refused until a public clear contract exists. |
| `clip.update` trim preview | Existing `clipTrimPort` → `clip.trim`. Admit only the native trim preview shape: one parent literal clip, `source: 'clip.trim'`, and the exact `from`/`to`/`hold` (plus native-preserved `speed`/`app` where present) payload produced from the original source-window capture. Convert to native `in_s`/`out_s` using the original basis, never by recapturing after an ACK. | Parent literal clips only. Occurrence clips, arbitrary `clip.update` source-window changes, `mode`, clear-based trim, time maps, and trim that needs intent-container removal are refused. The native session's existing “session scalar clear preview” dependency remains a refusal, not a lossy fallback. |
| `clip.add` | Existing `parentClipAddPort` → `clip.add`. Require a complete explicit nonmedia row: target equals `row.id`, stable `track`, string `clipType`, finite non-negative `at`, positive `hold`, and all remaining authored fields carried literally. The track must already exist and be active. | Parent only. Native `clip.add` rejects media/image/video/audio types, all asset/media selectors (including null), alternate timing codecs, source URLs, source windows, time maps, nested children, relation fields, and unsupported intentions. Minimal generic add, auto-track creation, media/import add, occurrence add-media, and popup swap are not this path. |
| `clip.remove` | Existing parent `clipDeletePort` → `clip.delete`, one target and no payload. Capture/resolve against the raw parent collection and retain whole-row/dependency/selection claims. | Parent ordinary clip only. Projected occurrence deletion, legacy shot ownership, nested clips, group deletion, relation-bearing clips, and ambiguous display IDs refuse. The current session wrapper intentionally requires `ownerRef === 'parent'`; do not infer occurrence ownership from the displayed ID. |
| `track.add` | Existing `trackCreatePort` → `track.create`, only when the generic payload is sufficient to form the exact explicit row `{id: target, kind, label, role}` and no `before`/auto-placement semantics are requested. Use the target as the caller-supplied row ID, not an inferred ID. | Parent collection only; no child/new-occurrence lane. Generic `before` ordering, opaque row fields not represented by the patch contract, and any mixed move/create dependency not captured as one native command are refused. This is a useful second slice but should land with the batch seam, not as a separate submit. |
| `extension.noop` | Pure no-op; it is not a writer. It may be accepted alone without a durable command, but a mixed patch must still be classified as a complete batch and report its semantic intention in the returned diff. | No other generic family is implicitly filtered out. |

Everything else stays outside the first native consumer: `track.update` non-label, `track.remove`, `asset.update/remove`, `app.update`, `project-data.write/delete`, `clip.split`, `clip.slice`, graph operations, media clip add/swap, occurrence add/delete/duplicate, placement, group operations, split, source/media import, visual seam/transcript/project-data writes, and element operations. Existing relational media-preparation/catalog writes are not canonical timeline command coverage.

## Required implementation seam

These are the smallest edits for the next consumer cut; no schema, Runtime, UI, root, pin, or Composition change is implied.

1. Add a `GenericPatchCapturePort` beside the existing gesture ports, with `capture({ patch, current })`, `finish(basis)`, and one `submit({ commands, preview })`. Its implementation belongs in the command session, not in the generic compiler. Capture must classify every operation first, then invoke the existing capture/executor functions against one raw bundle in patch order (respecting `order`). It must retain each original basis, native command claims, created IDs, owner/selection reads, and the complete unsupported-operation list.
2. Extend `commands/commitSession.ts` with one batch enqueue path using its existing `Payload.commands`, `before`, `after`, and `preview`. It must execute all prepared native commands against the current raw bundle to verify original claims, then call `enqueue` once. `commitSession.ts:pump` already serializes the command array in one `/commit` request; do not call individual port `submit` methods from the generic adapter. Existing per-gesture ports stay unchanged.
3. Expose that batch port through `hooks/useTimelineCommandSession.ts`, wrapping it in the same `legacyClean`/session-closed guards as the existing ports. Pass it from `hooks/useTimelineState.ts:790` into `useTimelineOps`; add only the needed typed fields to `UseTimelineOpsArgs` and the state context. The local `project()` path must use the native preview projector for each supported command and `commitData(save:false, skipHistory:true)` only for display projection.
4. Change `hooks/useTimelineOps.ts:271-303` to classify the full patch after editability/version/validation. For an all-supported patch, capture/finish/submit the one batch and return the existing semantic diff. For an unsupported operation or unsupported combination, throw one structured error containing every operation index/op/target and reason before any submit or `save:true` call. Do not use `compiled.nextData` for either local authored state or persistence. Keep `validate`, read-only `preview`, live version checks, and `flush` contracts unchanged.
5. Update `hooks/useTimelineCommandsService.ts` only at the bounded public methods: route nonmedia parent `addClip`, native parent `deleteClip`, `setClipParams`, exact trim, native move, parent label, and exact `addTrack` through the same session ports/batch seam. `updateClip` must refuse unsupported fields rather than sending a snapshot mutation once a field is claimed by this consumer. Do not broaden this into a generic `if (port) native else legacy` branch. The command facade must either emit the native command or return the visible refusal result.
6. Leave `runtime/extensionContextFactory.ts` and `lib/proposal-runtime.ts` as delegating wrappers, with only diagnostics/tests added as needed. `ProposalRuntime.accept` already leaves a proposal pending when `timelineOps.apply` throws because the accepted transition is after the call. It must not mark an unsupported mixed proposal accepted or discard its full patch. Scope validation still runs before native classification.
7. Keep `runtime/element-adapter.ts` out of this cut. Its direct CAS writer remains a separately tracked unconverted ingress until Agent publishes an element command contract with explicit overlay IDs, element identity/revision, params, fades, transitions, and inverse/rebase semantics. Do not add a generic snapshot fallback or pretend `clip.set-params` covers `elementRef`/overlay creation.

## Atomic mixed-patch rule

The batch port must preflight every operation and build every native command before `submit`. If any member is unsupported, no member is submitted. Examples that must refuse as one complete draft include:

* nonmedia parent `clip.add` plus media `clip.add`;
* parent `clip.add` plus `project-data.write`;
* scalar `hold` plus unsupported opacity/effects/position in one `clip.update`;
* parent label plus child-track label or `track.update muted`;
* parent delete plus occurrence delete;
* any operation using a selected-pack PARAM value without verified native inputs;
* compiler-canary source-map data plus its main clip patch.

The refusal reports all intentions, not only the first unsupported member. The proposal remains pending; a direct facade result retains the caller's draft/error input; the command outbox has no new intent. There is no filtering of supported members and no independent submit. A subsequent explicit caller retry after a fresh read may build a new patch; the bridge never recaptures the original basis after an ACK.

Absolute/relative rules are likewise closed: `clip.move` uses the native absolute `on` semantics; trim converts source endpoints from the original captured row; add uses the producer's explicit literal `at`/`hold`; no operation reselects by display shape, prefix, or refreshed ACK state. Created add/track IDs are reserved by the producer before capture and reused on retry.

## Original tests to preserve and replacement recipe

The current generic positives must remain behavior positives, with their harness changed from a snapshot `commitData` spy to the native batch port where the operation is in the cut:

* `useTimelineOps.test.ts`: “commits exactly once with semantic:true and save:true” (replace the save assertion with one native command request plus local preview), “the native commitData receives the compiled nextData (not a clone of the original)” (replace durable assertion with exact native preview/raw basis), “a single apply call produces one undo stack entry via native onBeforeCommit”, “consecutive apply calls each go through the native commit path”, and the `clip.add` positives in the version section, especially “does NOT reject when patch.version is 0 (no-version-expectation bypass)” and “accepts patch when version matches current configVersion”.
* Keep the full-batch behavior tests: “rejects the entire batch when any operation is invalid”, “rejects a batch with an unknown operation family”, and “rejects stale batch even when some operations are valid”. Add a positive generic mixed supported batch and assert one request/one accepted publication/one undo unit, not one request per operation.
* Keep all read-only tests unchanged: “rejects apply before commit and leaves the input snapshot unchanged”, “rejects setAllTracksMuted through guarded apply without committing”, and “keeps validate and preview available while edits are denied”. Read-only must fail before native capture or outbox append.
* Keep proposal tests: “accepts a pending proposal with matching baseVersion”, “accepts proposal with baseVersion 0 (no-expectation bypass)”, “applies only through TimelineOps (never bypasses)”, “accept revalidates against current reader snapshot (not cached version)”, “never calls TimelineOps.apply for a stale proposal”, and “marks proposal stale before mutation when baseVersion differs”. Add pending-on-native-refusal and all-intentions diagnostics cases.
* Keep native source positives that define the mapping: `clipScalarCapture.test.ts` “matches all three frozen App fixture commands, records, and authored output exactly”, “keeps shared occurrences isolated and preserves opaque/unrelated data”; `clipParamsCapture.test.ts` “preserves explicit clear, empty-key and null values while leaving opaque siblings untouched”; `commitSession.mixed.test.ts` “recovers label → params → trim with the original guards and exact lost-ACK request”; and the parent-add/delete/trim/track-create exact request, identity, recovery, and refusal tests.

Replacement zero-legacy/reload/retry/undo recipe for each supported family:

1. Seed a raw accepted bundle with parent and occurrence candidates, opaque roots, null/absent/empty values, order-sensitive arrays, and own `__proto__`, `constructor`, and `prototype` keys. Capture before preview; assert the generated native command contains the original owner, selection, reads, bindings, writes, and created IDs.
2. Call one generic `TimelineOps.apply` (and one public facade/proposal equivalent). Assert zero `saveTimeline`, `saveTimelineAtHead`, `publishParentComposition`, `config-replaced`, or other legacy traffic; assert exactly one command-session append and one `/commit` body containing the complete ordered command list. A mixed patch must use one request.
3. Assert local projection is native and display-only (`save:false`, `skipHistory:true`), then `flush()` and reload. Compare the complete accepted authored closure, including opaque roots, explicit absence/null, array order, owner/occurrence isolation, and created IDs. Do not compare only normalized rows.
4. Force a lost acknowledgement and restart/reclaim the outbox. Assert identical request body and retry key, no second capture/allocation, and dependent edits held behind the original command. Change a relevant field after capture and assert the original command is refused with the draft retained; change a disjoint field only where the native command's recorded guards permit it.
5. Undo the one accepted publication through the command session/Runtime history and redo through the existing guarded path. Assert exact authored restoration, one history unit for the generic batch, and no legacy write. Include A→B→A and created-ID dependency refusals.
6. Repeat with stale `version`, `version: 0`, matching version, read-only editability, unloaded data, provider/session unavailable, and unsupported mixed operations. Stale/read-only/unloaded/refused cases must leave canonical data, accepted head/history, outbox, and draft unchanged while reporting every operation intention.

The existing native command/session tests already cover most of steps 3–5 individually. The missing evidence is the actual generic adapter and public/proposal ingress using the one batch port, plus zero-legacy spies at those seams.

## Deletions this cut permits

Only after the recipe passes for the exact family may its old generic snapshot branch be deleted: the `useTimelineOps` `commitData(save:true)` path for covered patches, the label-only special case, and the corresponding public-facade `applyValidatedMutation` call for that family. The generic compiler may remain for validation/diff/read-only preview until every family is native, but its normalized `nextData` must no longer be a durable write. This cut does not permit deletion of the global snapshot publisher, popup `saveTimeline`, placement CAS, duplicate/group publication, element adapter save, split fallback, registry writer, or whole-document compatibility path; those remain open until their own command contracts and accepted zero-legacy journeys qualify.
