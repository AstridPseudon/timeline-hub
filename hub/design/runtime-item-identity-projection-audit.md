`dict.get` falls back on key absence, not falsiness: a present null/non-string `item_id` is invalid even if `id` is a string. SQL `COALESCE` would fall back on JSON null, but these validators do not admit that payload as a normal stored source. This is not an established alternate-ID bypass. Unknown nested keys and values never enter the item membership set.

`runtime_protocol/shot_dependencies.py::_descriptor` recognizes only descriptor-owned `source_item_id`/`source_item`, with object `metadata` taking precedence; Agent's equivalent is `astrid/packs/shots/dependencies.py`. The dependency analyzer's separate row-facing `id`-first access is not used by this commit source join or SQL projection (no Runtime caller of `analyze_invalidation` exists in these sources). SQL rows already expose the canonical physical identity as `id`. Its spelling does not establish an accepted raw-payload exploit.
