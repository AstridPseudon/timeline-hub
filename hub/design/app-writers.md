The current recipe also uses `rationale`; R4 internal `reason` is not an additional request field. Runtime failure `details.reason` remains a separate machine discriminator. One completed gesture emits one atomic command batch/undo target. Equal `group_id` across accepted requests does not fuse them into one target; a multi-publication inverse explicitly lists every target and guards the entire transaction under the Agent-defined schema.

The states below must remain distinct:

* **Preview:** `useTimelineCommit` preview hydration (`useTimelineCommit.ts:249-290`), patch/compiler preview, and command-runner dry runs. These update render state only and must not save, create history, or create a draft.
* **Local/unsent history:** `useTimelineHistory`'s in-memory undo/redo stacks (`useTimelineHistory.ts:212-218`) and command inverse descriptors. A local undo currently calls `commitData(..., {save: true, skipHistory: true})`; it is not accepted Runtime history until the resulting request is acknowledged.
* **Durable local recovery:** IndexedDB drafts (`timelineDraftIndexedDb.ts:160-233`) contain unsent data, base-head metadata, and eventually the exact pending request. They are crash recovery, not accepted history.
* **Accepted durable history:** Runtime's acknowledged commit/publication receipt and `shotComposition.listHistory`/`restoreHistory` (`useTimelineHistory.ts:553-609`). A provider checkpoint or a successful whole-document save is not interchangeable with the future EditCommand receipt.

The current editor flow is generally:

```text
gesture / facade / import
  -> local TimelineCommand or TimelinePatch (when applicable)
  -> useTimelineCommit.commitData/applyEdit
  -> useTimelinePersistence draft + current provider saveTimelineAtHead
  -> Runtime publishParentComposition (/v1/.../composition-revisions)
```

The migration flow is the same local intent boundary followed by an EditCommand request to the one `/v1` commit door. No App producer should call an old `/astrid/v1` save route, a Supabase config-replacement route, or a compatibility whole-document fallback after its command producer is migrated.
