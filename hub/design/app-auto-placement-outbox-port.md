# Automatic placement outbox port — storage-only candidate

Source: `/home/user/work/wt/app-m2-auto-placement-outbox-storage/src/tools/video-editor/commands/commitOutbox.ts`, based on D13 `c195d1ee1`. This is a local storage port, not task/placement authority or activation.

The existing `astrid.command-outbox` / `owners` record gains optional `placementContinuations`. The scope already binds authenticated realm/actor and canonical project/timeline. All methods require the existing explicit owner claim/browser lock/generation. No credentials or worker lease authority belong in these records.

Three implemented claimed-owner methods:

- `reservePlacementAdmission(id, input)` freezes a caller-stable continuation ID, the normal prepared `OutboxRequest` (POST `/v1/tasks`, exact serialized body/key), original head pair, `readClosure` (existing immutable pins/read closure, not another document/provenance authority), raw `ownerRef`, explicit `anchor`, `lane`, `fallback` (null means explicitly absent), `policy`, approved `output` selector, `autoApprove: true`, and preallocated `createdIds`. Missing fields/approval refuse. Await success BEFORE task POST; no transmit callback is supplied here. Repeat with the same ID must match the frozen input; never regenerate the request on unknown outcome. Reserve only after the ordinary unsaved queue has been ACKed; this slice refuses a nonempty queue rather than silently substituting preview/current head.
- `recordPlacementTask(id, request, {projectId, runId, taskId})` atomically attaches an adapter-validated normal locator to that exact reservation. Project must match the owner; locator is immutable and detached. Unknown admission outcomes retain the original bytes/key without a locator. Caller validates the authenticated response before recording it.
- `capturePlacement(id, mediaPin, capture)` requires a saved task locator and first durably reserves the adapter-validated immutable selected-media pin. A changed pin refuses; interrupted capture must reuse the saved pin. No callback runs if that reservation aborts. The future Agent adapter callback receives the detached ORIGINAL continuation (including that pin) and returns the original guarded command payload. It must reread the exact saved task/output, validate normal managed selection, capture against the saved immutable head/read closure/raw policy, and consume the saved birth IDs. Storage creates one ordinary queued intent with original head/guards/pin/payload and links it to the continuation in ONE transaction. An aborted transaction queues zero intents; a committed one queues one. Duplicate calls after linkage return saved work without invoking capture. Same-claim overlapping captures refuse. Capture failure retains the original continuation with a visible conflict and queues nothing; it never recaptures against a newer head or silently retries a refused capture.

`dispatch` remains the ordinary commit port, retaining the exact pending request/key. Its existing ACK transaction also stores continuation -> intent -> accepted head/value before pruning. Later B/C or `timeline.inverse` acceptances cannot erase/rearm the link. Cancelling an unsent linked intent retains a cancelled link, so completion cannot enqueue it again. Original pin and reserved IDs remain retained with the continuation. The payload must include all original command guards/bindings and any pin material required by the ordinary request builder; storage does not invent command DTO fields.

`list(scope)` returns ALL matching owner records, including task-only and accepted-only owners. The existing method now accepts authenticated `{realmId, actorId}` with optional canonical project/timeline filters, allowing reconnect discovery before mounting any editor; the full-scope call retains its old exact matching behavior. Claims still require the complete saved canonical scope and explicit owner ID. Consumers must retain owners with `placementContinuations?.length` when filtering for recovery; the current session's intents/pending-only filter is NOT activated/changed in this storage slice. Recovery rereads saved task IDs, independent of event/cache delivery, with the original scope and explicit owner claim. No background coordinator or network work is introduced.

The callback contract is deliberately local and prevalidated, like the D13 carrier. JSON is not authority: Agent/Runtime must supply the deterministic recipe, immutable closure/media pin and normal guards. Callback output cannot invent wire fields, inline provenance/hashes, attempt fences, or credentials. Prepared task bytes/response decoding, canonical scope/approval/output validation, completion discovery and actual dispatch remain separately scoped consumer work. Storage alone proves none of those Runtime semantics.

No cleanup/expiry/retention framework or destructive clear API: retain linkage until an explicitly authorized caller checkpoint is designed. No task posting, UI/session activation, native capture, pin client, Runtime client or wire changes. Tests use the existing IndexedDB fixture and transaction-abort harness, not browser crash/fsync or Runtime acceptance.
