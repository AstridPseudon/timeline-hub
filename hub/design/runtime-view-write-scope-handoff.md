## Contract and staging

Existing `POST /v1/projects/{project_id}/timelines/{timeline_id}/views` persists project-owned artifacts. It now requires `projects:write` (or existing admin authority) and an explicit valid `Idempotency-Key`; independent `objects:write` is unnecessary. `projects:read` alone returns the existing authorization error (401), and missing/invalid keys return protocol error (400), before ingestion. `POST .../inspect` stays `projects:read`, needs no key, and does not persist anything. The browser door still denies `/views`; this correction does not add a door route.

Python official signature: `create_timeline_view(self, project_id: str, timeline_id: str, options: Mapping[str, Any] | None = None, *, idempotency_key: str) -> Mapping[str, Any]`.

TypeScript official signature: `createTimelineView(projectId: string, timelineId: string, options: Record<string, unknown>, idempotencyKey: string): Promise<Record<string, unknown>>`. Pass `{}` when there are no options.

Callers allocate one key per logical view request and reuse it with the identical project/timeline/options on transport retry. A fresh request (including refreshing the current head) gets a new key. Same timeline/key with different request input refuses with 409 through the normal command replay policy. Identical retries return the original view, even when the current head has advanced, within the existing 24-hour mutation result replay window. Artifact IDs, bytes, project custody, response shape and deterministic cross-key content dedup remain unchanged; artifact reads survive restart independently of that replay window. No receipt wrapper is added to the response.

**0.2.12 is STAGING ONLY**, generated normally on this branch from `generators/release.json`; the connector fix separately stages 0.2.11. Neither is a frozen public consumer target. Runtime manager must compose the connector and security fixes once, regenerate/check the final tuple, then publish `runtime-current-tuple.md` as the single paired consumer target. Earlier 0.2.9 and 0.2.10 are affected by F1/F2. This worker does not publish a tuple, repin a repository or release either package.

## Restored composition publication

The same OpenAPI change documents the existing compatibility route without altering its guards: eligible untracked matching-head publication or genuinely empty headless/fresh publication with `expected_head=null`; tracked heads use commands. Stable 409 `details.reason` values: `timeline_commit_required` (tracked head), `stale_head` (untracked head mismatch), `headless_content_not_empty` (authored/scoped legacy content, including project documents). Wrong-project 409-vs-404 remains the approved backlog item. Other retired operation removals remain with their consumer migrations.
