## Prioritised follow-ups

1. **am-discord eased/fractional camera plus word-targeted focus plus `composer` schema (#1, #3-lite, #17). S–M, Agent pack only.** This directly delivers what the user asked for (staggered, dramatic zooms on "very / next / day") through the normal export path. It is back-compatible (steps without `frames` still snap), and the maths already exists in am-presenter. It needs the owner's OK because it changes a shared built-in (new revision; existing pins hold). It does not overlap shot-layering.
2. **Make the project-pack route honest and then real (#6 now, then #7/#8/#9, #4, #5).** First (S): block or warn on project-pack refs in App exportGuard and `timelines check`, so nobody ends up with a preview-only timeline. Then the cheap admission fixes (S each: type-only import exemption, default build command with pinned Node). Then occurrence-aware update-element (M). Last, render loading of admitted project packs (L). That last item is the "element parity" piece that the extensibility plan defers to Phase 3 after the shot-layering release. Recommend pulling the narrow version forward: project-pack snapshots in the render registry, with no new registry. Without it, customising an element can never reach export.
3. **CLI trust fixes: one shared diff counter (#14–#16), scoped `--gap-after` (#12), and the SDK set() memory fix (#11). M each.** These caused wrong or misleading results and a silent no-op. #14 overlaps the shot-layering `differences()` normalisation (§3.2), so do it in or just after that release. #11 also needs the SDK to fail loudly (no partial or "looks done" state) on large films.

Not recommended now: generic clip-level continuous effects or eased keyframes for element clips (#2, L). It belongs to extensibility Phase 3 and the shot-layering export-isolation follow-up (F1: effect-layer renders null in export). #1 covers the user's need without it.
