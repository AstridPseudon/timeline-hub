## Minimal proposed follow-up and decision

**Decision requested from orchestrator:** authorize a separate bounded ordinary-owner cleanup change, and keep all staged task/init cleanup closed until the composed requester handoff is accepted. No immediate product change is part of this audit.

For the ordinary slice, consider **one just-created current-code owner at its explicit successful close**, under its existing exclusive lock and generation. Do not scan old owners or all projects. First settle submitted append/projection work and verify no intents, pending request/outcome, prepared capture, draft/generation gap, active sender or any creation/init/render/placement/unknown retained field. A live late-dependent append must remain possible until this terminal boundary. Never delete inside the generic ACK transaction merely because the queue became empty.

Use the existing normal history receipt and immutable accepted identity to prove the final ordinary publication. A finite check can inspect at most one existing history page and the matching immutable closure; missing publication, incomplete pagination/proof, changed identity, lock contention or any error means **keep the row**. Recheck the exact owner/generation/unchanged candidate in the same strict transaction as deletion, with no network inside that transaction. Never replace success with guessed completion when a write/quota/abort fails. Older records, foreign scopes, busy owners and unknown shapes are deliberately retained; this is not a claim to bound total historic storage. Entirely empty current-lifetime owners are a separate trivial candidate only when the same close/draft/in-flight conditions hold.

For staged owners, keep the whole checkpoint until **all** of that owner's original handoffs finish. A later bounded explicit owner pass may remove only a proven finished checkpoint using existing history/task receipts; no timeout, lease, purge, database, background coordinator, replacement wire or local completion ledger is needed. It must not rely on local tags, a task locator, equal timeline bytes, a mutable head, or receipt-shaped JSON alone. In particular:

- Render: prove original task admission identity and durable task/output handoff, and where a producer proposal exists, the requesting client's exact accepted proposal publication/receipt with real attempt/guard authority. The worker never commits. Historical A stays historical after head C or undo.
- Placement: normal task/managed-output/media-selection proof plus accepted guarded command publication must establish original consumption independently of current geometry. Undo does not unconsume it. Late notifications may **resume an existing saved approval only**; an absent/pruned checkpoint must not cause reserve/recapture/rearm. A new deliberate user approval is separate from a late event. If this cannot be established with existing authority, retain the checkpoint. Do not add a tombstone framework to hide that missing contract.
- Init: prove original create/H0 and native init publication through history/immutable reads, then finish deterministic selection and Main/additional metadata CAS or verify the concurrent winner. Returning `loadLatest`, an init tag or merely receiving its ACK is insufficient to delete the owner. Keep original retry/request/default data while proof/CAS is incomplete.

Before any task/init cleanup, compose existing ACK hooks together: creation retention, independent init checkpoint, D13 render retention, placement acceptance/cancellation, dependent readyBase and rejected-prefix handling. Bootstrap and D13/requester are separate source branches; replacing either entire outbox file would drop the other's behavior. Their combined lifecycle was **not executed** here.

Final activation also requires the official Agent/Runtime release pair and actual requester proposal/capture acceptance. The observed Agent [registry:34](/home/user/work/agent/astrid/sdk/timeline/commands.py:34) still registers clip.move/track.create/track.set (inverse/restore separately); no native init/automatic placement/producer.guard registration or live proposal acceptance was proven in this audit.
