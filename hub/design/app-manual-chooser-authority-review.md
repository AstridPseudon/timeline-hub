## Blocking source finding: P2 — display names can select the wrong binding

The adapter gives every option a distinct local ID, but builds its name solely from uncontrolled raw shot name, occurrence ID and child-track label ([runtimeRecoveryDestinations.ts](/home/user/work/wt/app-m2-manual-chooser-authority-review/src/features/tasks/components/TasksPane/utils/runtimeRecoveryDestinations.ts:103)). The actual reused selector gives cmdk **`value={shot.name}`**, while its `onSelect` closes over `shot.id` ([ShotSelector.tsx](/home/user/work/wt/app-m2-manual-chooser-authority-review/src/shared/components/selectors/ShotSelector.tsx:302)). cmdk's keyboard selection is name-valued. Equal names select multiple rows; Enter dispatches the first selected item. Thus the unique chooser keys do not guarantee unique selection. The chooser subsequently looks up that wrong key and forwards the corresponding frozen binding ([RuntimeRecoveryChooser.tsx](/home/user/work/wt/app-m2-manual-chooser-authority-review/src/features/tasks/components/TasksPane/RuntimeRecoveryChooser.tsx:82)).

Two private failures reproduce this with the real RuntimeDataProvider, real ShotSelector and normal in-memory read transport:

1. **Ordinary case:** two visual tracks in one occurrence have distinct IDs `raw-child-track` / `alternate-child-track`, both labelled `Picture`. Open selector, ArrowDown, Enter, supply explicit timing, request the recording callback. Expected `alternate-child-track`; received `raw-child-track`. The paired control changes only the second label to `Alternate picture` and passes, establishing that the interaction correctly targets row two with unique names.
2. **Different occurrence:** occurrences `Scene` and `Scene · Main` share a shot whose child tracks are labelled `Main · Detail` and `Detail`. The first and last option both display `Shared shot · Scene · Main · Detail`. Clicking the last row correctly retains `Scene · Main` / `alternate-child-track`; keyboard End then Enter routes to occurrence `Scene` instead. No rule permits assuming a raw ID cannot contain this delimiter.

Counterexamples are outside notes: [app-m2-manual-chooser-authority-review/authority-controls.test.tsx](/tmp/claude-0/-home-user-repo/7dc61be1-7066-52e0-a5d0-94f90e61430a/scratchpad/orch/workers/app-m2-manual-chooser-authority-review/authority-controls.test.tsx:143), with the cross-occurrence case at line 171. Final log: [app-m2-manual-chooser-authority-review/notes/controls-final-eight.log](/tmp/claude-0/-home-user-repo/7dc61be1-7066-52e0-a5d0-94f90e61430a/scratchpad/orch/workers/app-m2-manual-chooser-authority-review/notes/controls-final-eight.log). These expectations remain ordinary failing assertions; no product expectation was rewritten, skipped, or weakened.

**Minimal fix:** make the chooser's option names unconditionally unique for the existing name-valued selector, for example by prepending each frozen binding's unique local ordinal with a fixed separator before the descriptive raw name. Keep the separate frozen raw binding and ID lookup; never parse the display name back into ownership. A literal unique ordinal prefix avoids delimiter/control-name collisions without changing the shared selector API. Add the two keyboard regressions to the normal chooser suite, preserving the unique-name and mouse controls. Do not connect a writer as part of this fix.

The shared selector's name-valued behavior predates this branch, but this branch introduces a caller with multiple child destinations whose names can legally collide. This is a source qualification HOLD for the new caller. **No actual wrong canonical write is demonstrated:** TasksPane supplies no native callback.
