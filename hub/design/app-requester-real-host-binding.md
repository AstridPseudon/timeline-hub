## Minimal connector host contract request

**Owner requested: the existing local authenticated connector/host owner.** App has no current host object that can truthfully implement the following. Do not construct an adapter until that owner identifies and supplies the actual owned lifetime. This is a request on the existing local callback seam, not a new authentication service, endpoint, wire protocol, broad store, or persisted generation scheme.

1. Supply the existing `isCurrentIdentity(expected: { realmId: string; actorId: string }): boolean` alongside operation callbacks from ONE authenticated host lifetime. Return literal synchronous true only for that lifetime and expected nonempty identity; false/throw while absent, negotiating, invalidated, fenced or disposed. `getRecoverableIdentity`, admit/get task, managed-output/media-selection reads, and exact-request transmit must close over the SAME host/client, selected base, credential handle and transport. Native capture, when separately provided, must also be invoked under that host lifetime; do not draw authority from editor selection.
2. The host must synchronously retire its old bound callbacks BEFORE its own base, selected upstream transport, credential handle, actor/realm, reconnect or fence transition, and on owner cleanup/unmount. Equal-string reconnect/credential replacement is a new lifetime. Retired callbacks never become current merely because strings match again. A fresh authenticated negotiation may create a new binding; it cannot revive old work already in flight. Keep this local to the actual host; do not persist a new outbox field.
3. Enforce the same lifetime at actual transport dispatch after async client waits, not only when entering an App wrapper. The requester checks directly before callbacks ([src/tools/video-editor/commands/placementRequester.ts:200](/home/user/work/wt/app-m2-requester-real-host-binding-audit/src/tools/video-editor/commands/placementRequester.ts:200), 236) and inside outbox mutation callbacks; AstridRuntimeClient itself awaits ensureSession and pre-write health afterward. The host must not silently forward an authorized-old callback through a newly selected proxy credential. Unknown outcomes retain exact bytes/key and saved bindings; existing requester/outbox logic handles recovery.
4. State the honest remote boundary: local invalidation can react only to host-owned changes and received rejection/disconnect signals. The browser cannot synchronously learn an arbitrary remote revocation or credential-file replacement. If the connector continues to select hidden credentials afresh on each HTTP request with no binding to the caller's host lifetime, this contract is UNSUPPORTED for that path. It must stay inactive. App must not bridge that gap by polling, identity equality, or naming cached handshake data “current authority.” No protocol/endpoint to solve it is proposed here.
5. Before delivering a supported binding, tests must cover successful same-client discovery/task/read/capture/transmit; absent/false/throw/Promise ports; base and transport replacement; credential revocation/rotation; actor/realm change; fence; unmount; reconnect in flight and completed with identical strings; invalidation in promise reactions and just before actual dispatch/storage callbacks; old session completion after retirement; exact retry on a new supported lifetime without recapture, ID reallocation or consuming an uncertain ACK. Use the current executable diagnostics to show precisely which previously unavailable guarantee the owner supplies.

This is the smallest actionable handoff: identify the real connector owner/lifetime first, then implement its narrow operation-bound adapter in owned `src/integrations/runtime` or the existing editor hook. No adapter can be truthfully filled in today from these sources. No automatic caller, producer preparation, task commit, pin update or wire change is authorized by this report.
