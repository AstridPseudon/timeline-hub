# Incoming transition policy — decision required before implementation

Design only, 2026-10-19; Composition base `63ab6e0`. PLAN and the approved 0.0.9 defaults apply. Reuses the five cases in [viewing-final-route.md](viewing-final-route.md); no probes or tests repeated.

## Core answer

**No existing admitted fact inspected selects incoming ownership for both App preview and Agent final export.** Canonical pins identify immutable data, not its transition convention; both producers can publish that model. Compilation preserves authored fields. Spelling, timing shape, occurrence membership, receipts and caller identity cannot supply the missing meaning.

**Contract question:** may the existing canonical parent/internal-timeline model define `clip.transition` as **incoming for every producer**, while explicit native compiled `TimelineConfig` keeps its outgoing default? Previously outgoing canonical revisions, including Agent publications, require explicit correction/migration authorization. If both conventions must coexist in that same model, identify a persisted semantic distinction or separately authorize a contract/migration change. No safe selector exists today.

Existing counterexample: the same pinned child `[a@0,b@1(fade/.4s),c@2]` at 30 fps draws b with opacity .5/content frame 6 at frame 24 in App, while final Composition reads b's declaration toward c. **Two legitimate entrypoints already disagree on identical immutable data.** Runtime's boundary predicate also reads incoming b; Agent's validator checks its successor.

**Conditional API:** export `TransitionInputPolicy = {ownership: 'incoming'; incomingPolicy: 'preroll-crossfade'}` from root and `./evaluation`; add `transitionPolicy?: TransitionInputPolicy` to `TimelineCompositionProps` and as the last optional `prepareCompositionScene` argument. It is a render option, never authored metadata. Composition resolves each clip's incoming declaration and owns all clocks/aliases/caps/opacity in shared render/scene preparation. The existing outgoing-pair opt-in stays valid.

**Caller boundary after ratification:** App canonical projection → `TimelineRenderer`/public preparation; Agent admitted canonical snapshot → trusted generic-host adapter → existing backend-config port → `RenderRequest` → root props and `host-scene.ts`. Both derive from the same pinned source contract; App's local payload supplies no render authority. Native inputs omit policy. Without a binding source contract, **do not implement selection**. Exact plumbing is in slice 2 below.

For existing rounded own start/duration S/D and positive transition frames T, P=T with a same-track predecessor, otherwise 0. Origin R=max(0,S−P); exclusive H=min(R+D+P,E), omitting E when no canonical occurrence cap exists. H≤R mounts nothing. At F∈[R,H), contentFrame=F−R, ownFrame=clamp(F−S,0,D−1), opacity=clamp((F−R)/T,0,1). Reuse existing speed/trim handling; outgoing opacity stays 1, gain/envelopes unchanged. No inclusive extra frame.

| Existing case (30 fps, D=30) | Proposed half-open b mount without occurrence cap | Midpoint F: opacity / contentFrame |
| --- | --- | --- |
| Adjacent S=30,T=12 | [18,60) | 24: .5 / 6 |
| First S=60,T=12 | [60,90) | 66: .5 / 6 |

| Overlap S=15,T=12 | [3,45) | 9: .5 / 6 |

E=ceil((occurrenceStartMs+occurrenceDurationMs)×fps/1000); E=60 excludes frame 60, including oversized. Preserve oversized duration after origin clamping. No transition uses the own half-open span. Incoming `fade`/`crossfade`/`cross-fade` mean linear incoming-only opacity. Reject malformed/conflicting policies and unsupported parameters/implementations; keep their host path. Planner support does not widen Runtime admission. Omission keeps outgoing/default own-span/dip/half-open behavior; D1/D2/`assetEntry` are unchanged. Retain the old host until migration/correction is explicitly authorized.

## At most three implementation slices, after the answer

1. **Composition public preparation:** add the option and resolve incoming declarations by clip index, including index zero, in `TimelineComposition.tsx` and the existing transition modules. Feed a separate incoming declaration vector through `SceneTrackInput`/`prepareScene` and an optional planner input; keep the outgoing pair vector and its fit/adjacency checks intact. Do not route incoming overlaps through the outgoing authoring helper's non-overlap rejection. Preserve existing reference-duration precedence; require positive finite safe-integer T after rounding and safe frame endpoints, without the pair planner's T≤D limit. Reuse `DrawPlan`, `queryDrawFrame`, `TransitionLayer` and existing speed remap. Extend `typescript/tests/{transition-spans,transition-policy,evaluation,scene-evaluation}.test.ts` for the table, first frame/end−1/end, capped oversized, aliases, invalid input, rational fps, speed/trim and unchanged gain; keep default and two-pair expectations. Test rendered Sequence/opacity/content against scene answers. No package pin change.
2. **Owned caller wiring:** Agent owns trusted snapshot → `backend_config['rendering.remotion']['transition_policy']` (new backend option on the existing port, no Runtime DTO) → backend `_CONFIG_KEYS`/settings → merged root prop `transitionPolicy`; `Root.tsx` already spreads props. Feed the same option to held `remotion/src/host-scene.ts`. App owns canonical source → Player/preparation plumbing. Derive managed policy after resolving admitted source, never accept a caller override of that source's convention or infer it from a raw `--timeline-authority` label. Agent's raw/native path stays omitted by default. Tests must use the same immutable parent/shot/internal pins for both callers, prove changed-head refusal and late child-head changes cannot alter selection, and exercise default native inputs plus canonical Agent-authored inputs. If the decision requires migration, specify and authorize it before this slice; a source-kind test cannot manufacture the missing contract.
3. **Real parity, then deletion:** extend the existing real-door mounted-button harness described in `viewing-final-route.md`, with matched package bytes, all five admitted/supportable cases, picture mismatch and independent audio/gain control. Keep original behavior expectations; use requirement-linked strict expected failures for an authorized temporary gap. Only after migration/correction approval and passing public/real parity delete the corresponding `VisualClipSequence` origin/duration/transition-opacity math and obsolete partial App transition adapters, replacing each removed behavior test with a named public equivalent. Keep custom/unsupported host branches and unrelated D1/D2 code. Version/pin/integration timing stays with the orchestrator after M1; none is authorized by this design.
