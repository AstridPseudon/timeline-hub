**Recommendation.** Keep the existing generated `Transport` seam. Add an ephemeral operation handle at the credential-owning local connector, with a dedicated local forwarding path that cannot fall back to ordinary rediscovery. Bind negotiation, task admission/get, managed-output/media reads and exact-request transmission to that one handle. Browser rebind/reconnect/dispose retires its old callbacks synchronously; server replacement retires the predecessor before reading discovery/credentials. Never replace a live handle's upstream or credential. The normal per-request discovery path remains available to existing consumers, including chat and read-only catalogs, but cannot authorize automatic placement.

The initial implementable scope is the same-origin App → Vite → App discovery proxy chain. The normal hosted page → Runtime browser-door chain bypasses this proxy and needs Runtime ownership/agreement separately. Do not claim that an App-proxy change supports that path. This is local connector work, not a Runtime `/v1` API, credential exposure, new outbox field, journal, relay or authentication service.

**Exact proposed local HTTP transport. All names below are new and pending agreement.**

Let `O = /runtime-config/v1/operation`. Vite forwards exactly `O` and `O/runtime/…` unchanged to the existing loopback discovery proxy, without its static Runtime Authorization header. Reject other descendants. No new listener or port. Normal `/api/runtime` and `/runtime-config/v1/workspace.json` retain their existing contracts.

| Request | Exact local response / meaning |
| --- | --- |
| `POST O`, `Content-Type: application/json`, body `{}`. Initial binding has no handle header; replacement carries one `X-Astrid-Operation-Handle: <old>` header. | After admission, retire `<old>` first, if supplied, **before** discovery/credential reads, including when replacement later fails. Resolve/validate one server-only snapshot and allocate a never-reused random 32-byte handle, encoded as 64 lowercase hex characters. `201`, JSON `{"schemaVersion":1,"handle":"<opaque>","identity":{"actorId":"…","realmId":"…","runtimeInstanceId":"…"}}`. Identity is selection metadata for policy checks; browser authentication still requires negotiation through this handle. No endpoint, path to credential, token, token hash or credential metadata is returned. |
| Any existing Runtime method on `O/runtime` + original generated path/query, with exactly one `X-Astrid-Operation-Handle: <handle>`. Example: `POST O/runtime/v1/tasks`. | Consume the local prefix and header, then dispatch the **unchanged** Runtime method, `/v1/…` suffix/query, body and idempotency key using that handle's fixed endpoint/bearer. Return existing Runtime status/body and allowed response headers. No Runtime operation field or identity precondition is added. |
| `DELETE O`, one handle header, no body. | Synchronously retire the server entry and abort owned requests before responding `204`, empty body. Unknown/already retired well-formed handles also return `204`; cleanup is idempotent. |

Controls and all bound replies use `Cache-Control: no-store`. Initial same-origin browser fetch uses `mode: 'same-origin'`, `credentials: 'omit'`, `redirect: 'error'`, `cache: 'no-store'`, and a handle-owned AbortSignal. Do not reuse immutable-object HTTP caching on this operation prefix: a cached response would bypass its dispatch/lifecycle fence. Existing unbound media playback caching/Range/ETag behavior stays intact.

Local failures have only `{"code":"…","message":"<fixed non-secret text>"}` with JSON content type and no-store: `400 operation_invalid` (malformed/duplicate handle header, invalid control body or suffix), `403 operation_origin_forbidden`, `405 operation_method_not_allowed`, `410 operation_retired` (missing/unknown/expired handle on the bound forwarding path), `503 operation_unavailable` (cannot acquire validated snapshot or registry is full). A received upstream 401/403/5xx or connector I/O failure retires the entry, aborts owned requests and returns fixed `503 operation_unavailable`, or closes a response already started. This lifetime failure is an uncertain retry, never an accepted ACK or permanent edit conflict. Do not serialize errors containing file paths, URLs with credentials, headers or token contents. A semantic 409/422 is not automatically a host retirement; retain ordinary conflict/refusal handling.

The dedicated forwarding prefix is deliberate. Adding only a header to `/api/runtime` is insufficient: a missing/stripped header would otherwise drop into its ordinary per-request credential reselection. `O/runtime/…` **never** falls back to `currentRuntime`, normal `/api/runtime`, a new binding, or automatic retry. Header values never enter the URL, Runtime headers, Runtime body, receipts, outbox, logs, storage or telemetry. The opaque handle is a short-lived local routing capability and must be treated as sensitive even though it is not the product bearer.

Admit control and bound paths only from the launcher's exact local App origin, with an exact configured Host at each listener. For POST/DELETE and other unsafe methods require one exact matching Origin; reject foreign/null/duplicate Origin. A same-origin browser GET/HEAD may omit Origin: permit that case only with `Sec-Fetch-Site: same-origin` and the exact Host. If Origin is present it must still match. Do not require browser code to set the forbidden Origin header, and do not accept Referer as authority. Vite's dedicated rule preserves these browser admission headers for the proxy and sets the expected proxy Host. The launcher supplies the exact allowed local App origin/server Host before startup; wildcard CORS or reflection is forbidden. Reuse `config/vite/astridProxySecurity.ts:9` for its exact loopback Origin/Host comparison where applicable, without changing its existing bridge semantics. Reject arbitrary absolute URLs, network-path URLs, fragments and dot traversal in the suffix; only an origin-form `/v1/…` suffix/query is forwarded to the captured endpoint. Strip the local handle, Host, Authorization, Cookie, Proxy-Authorization and hop-by-hop headers before adding the pinned bearer upstream; suppress Set-Cookie on replies. Keep normal permitted Runtime headers (including Idempotency-Key, Content-Type, Range and validators) and payload bytes. These guards are local browser admission; Runtime still authenticates and authorizes every request. This is not a defense against arbitrary processes already running as this user or malicious same-origin script.

**Where authority and retirement live.**

The App proxy owns an in-memory entry containing the opaque ID, immutable scalar endpoint/token and validated selection metadata, retired flag, and its active upstream requests. Build this snapshot from a single read of each relevant file and parsed object; combine existing loopback/product-profile/catalog checks rather than calling `currentRuntime` and then independently `readWorkspaceRuntimeConfig`. Concurrent external file changes cannot be made an atomic filesystem transaction by these reads; authenticated health/handshake/realm must agree with the selected snapshot or negotiation fails. Never reread files from a bound dispatch or mutate the captured connection. Never persist the entry or expose its token. Keep the Node forwarding primitive fixed as part of the entry's dispatch ownership.

The browser owns one small host per requester owner, with one current binding/attempt reference and terminal disposed flag. Proposed handwritten `src/integrations/runtime/operationHost.ts` wraps a **private** `AstridRuntimeClient` using its existing injected Transport, pinned normal base for diagnostics/policy, explicit expected identity, and private identity store. The transport sends to `O/runtime` with the captured opaque handle. It has no token. `bind()` first retires and detaches its old binding synchronously, then starts replacement acquisition; `dispose()` retires synchronously and is terminal. `reconnect()` means a new bind, including identical actor/realm/instance/token strings. Never call `AstridRuntimeClient.reconnect()` to revive a bound operation. Pending bind A completing after bind B/dispose must be discarded and its acquired server handle deleted; it cannot replace B.

Expose only the requester's narrow task/read callbacks, `getRecoverableIdentity`, `isCurrentIdentity`, exact transmit and retirement; do not expose the underlying client's session objects or a mutable `handshakeInfo`. One private client performs health, handshake and realm through the guarded transport. Validate actual authority field types, exact product scopes, required capability, supported schema digests, actor restrictions, realm agreement and existing expected-instance policy before setting the browser binding to negotiated. Copy validated identity scalars into private state before exposing any result; no mutable handshake snapshot survives as authority across an await. `getRecoverableIdentity` checks active before/after waiting and returns a copy. `isCurrentIdentity(expected)` returns a literal synchronous boolean: true only for this host's current, negotiated, unretired binding and nonempty exactly matching actor/realm. It returns false while acquiring/negotiating, after retirement/dispose/fence, or for mismatches. This callback has actual pinned-dispatch ownership behind it; cached session equality alone never sets it true.

All admission/get/managed-output/media-selection callbacks delegate to that private client. Exact transmit uses the **same guarded Transport**, validates saved method/path against saved scope, passes the original UTF-8 body and Idempotency-Key without parse/reserialize, and uses existing Runtime response/receipt validation and commit-failure classification. Do not instantiate `RuntimeDataProvider` (it constructs another client), use global fetch directly, or rebuild the saved request to send it. The integration adapter's accepted response checks remain required: a preview or absent/invalid receipt is not an ACK. If sharing its decoder requires a small extraction, keep one decoder; this design does not authorize a second acceptance model. Native capture must separately be bound to the same requester owner and checked before/after its await; no native capture transport or activation is supplied here.

Retire browser state immediately on local rebind/reconnect, selected-base/transport replacement, fence, dispose/unmount, received auth/unavailable/connector-retired response, failed negotiation, transport/body error or abort. Retirement aborts pending fetch/body work, clears identity, prevents new dispatch and ignores late success. Cleanup DELETE is best effort and never restores local liveness if it fails. Requests can have reached Runtime before retirement: abort/dispose does not undo acceptance. Keep unknown exact request/key, original approval, created IDs, saved media/task/attempt bindings and outbox claim semantics unchanged.

On the server, explicit DELETE or replacement marks retired before aborting streams. Check active just before invoking the Node upstream request primitive, with no intervening await. If parsing/buffering/connection work awaited first, check again after it. Abort every tracked request on retirement; check active in response/header/body callbacks before forwarding useful results. Once upstream dispatch began while active, acceptance may happen later and is uncertain if retired; do not claim a network rollback. Server close/shutdown retires all entries before releasing services. Process restart forgets the registry, so old handles fail closed.

To bound abandoned acquisitions without a new persistence/lease system, proposed initial limits are at most 128 live entries per proxy, 60 seconds of inactivity (reuse `IDLE_TIMEOUT_MS`), no expiration while a request is flowing, and expiry on the next inactive deadline. Expiry retires/forgets an entry; capacity failure returns 503, never silently recycles an ID or evicts someone else's live operation. Browser should release at the end of each finite requester pass and acquire anew for the next pass; a pending task does not require keeping a handle alive while idle. These limits are proposed local resource policy, not Runtime task/outbox expiry. Browser failure/abandoned create and many-tab tests must prove cleanup. A background browser timer is not the authority for server liveness.

**Honest synchronization boundary.**

Pinning means an external credential-file replacement does not replace the credential *inside an existing handle*. Old dispatch still uses the old bearer and upstream; it never adopts a newly selected actor behind a cached identity. The connector retires the predecessor before it deliberately rereads/reselects for a replacement. External revocation of that captured bearer, Runtime restart/port reuse, server expiry/crash or disconnection is observable only through received failure/change signals. Runtime remains the final per-request authority. A browser cannot synchronously learn another process's silent mutation, and a control response or SSE notification cannot remove that physical limit.

Accordingly `isCurrentIdentity` proves the locally owned negotiated binding, not synchronous remote credential validity, continued server registry presence, or an expected-instance precondition on Runtime acceptance. These are the same remote limits stated for the direct wrapper. Keep requester checks immediately before callbacks and **inside** outbox/IDB mutations; the transport's post-await fence does not replace them. If the required contract instead means “false in the browser before any external file/server change can affect any browser storage callback,” this proposal cannot provide it; that stronger requirement needs an owner decision rather than an optimistic adapter. No polling/per-request rediscovery/cached handshake workaround qualifies.

There are two dispatch boundaries, not a shared synchronous flag across processes. Retiring before browser fetch means no request is sent. Once browser fetch was invoked while active, the local HTTP request is in flight: it may reach the proxy/Runtime after browser retirement while DELETE/replacement is still in transit. The server fences after **server** retirement and before its own upstream dispatch; any earlier-dispatched request may remain uncertain. It always uses the old fixed snapshot, never the replacement connection. This design does not claim the direct wrapper's one-process flag can synchronously cancel a different process's not-yet-observed work. Tests must distinguish these boundaries rather than label a request already handed to HTTP as zero-dispatch. If strict end-to-end cancellation before any upstream bytes is required, escalate that stronger contract; do not claim HTTP abort proves it.

Fresh supported binding under equal actor/realm may retry the exact original request/key. Its handle differs, but the handle is stripped before Runtime and never joins idempotency scope. Old callbacks remain retired forever, old ACKs cannot be consumed, and new binding cannot recapture/reallocate/rearm the original work. Existing expected-instance/relaunch policy still applies; equal actor/realm is permission for retry scope, not permission to silently adopt a restarted instance. Do not weaken instance fences to make this design pass.
