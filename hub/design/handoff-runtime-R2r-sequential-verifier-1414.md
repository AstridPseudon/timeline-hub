# Runtime R2r sequential verifier callable interface (1414)

Runtime will add only the private `RequestCommitPort.capture_sequential_execution(capture: dict) -> None` seam (and the matching private RuntimeCommitPort protocol method). The method is request-scoped, detaches the full JSON carrier, requires the exact five top-level keys and `schema_version == 1`, and requires `capture.context` to equal the port's complete authenticated context (request, invocation, request hash, idempotency key, publisher and realm). It is consumed once by the immediately following `preview`/`accept`; a stale candidate, failed validation, or failed CAS cannot reuse it.

The carrier remains private: no PreparedCommit, request schema, generated client, public response, accepted-history continuation, or source-authority change. Runtime validates `prepared_digest` against the complete actual PreparedCommit, then verifies original command boundaries from the authenticated base and landing boundaries from the actual evaluated head. It binds every command/step/change/read ordinal, exact before image, owner/complete-owner set, managed edges, dependencies/effects, and unique source-to-landing physical correspondence. The original unlanded alias is never admitted as an accepted-history successor.

The Runtime verifier will pass only trusted per-command projections into the existing authentication path; missing proof on a staged moved-head alias remains `sequential_proof_unavailable`/closed, while ordinary existing ABI paths remain unchanged. No correction to Agent's settled carrier shape is required at this point. If Agent publishes a carrier whose `Execution` omits the command-boundary canonical images or whose `prepared_digest` excludes any prepared metadata, it is not callable and must be corrected at the Agent owner before qualification.
