The original whole clip row is consumed and checked as finite JSON, retaining conservative same-clip dependency; the wrapper also records actual original theme/fps input and occurrence start codecs. These reads are explicit operation-time declarations, never reconstructed from the final diff. The claim records original arguments, exact base pair, before/after authored digests, commands and reads in the existing save journal's `calls` field. No additional journal, executor, schema or authority carrier was introduced.

Save persists these claims; load need not trust or hydrate them. On publication, the adapter verifies the journal hash chain, selects the exact base pair and matching authored start digest, replays the original helper against the authenticated original closure, and compares the complete generated claim. Its final authored digest must equal the entire candidate. Only this complete single-helper capture receives `merge=fields`, its actual reads at request and step level, and a step patch/ordinal. Runtime/provider still verify the generic patch, previous values, reads, bindings and acceptance. No caller-generated recorder facts or media authority are submitted.

`fetch_bundle` retains the exact original publication ID in existing `base_parent` metadata. For an initially unhydrated production open, it reads all history pages, requires a unique revision match, then calls the existing publication-bound `open_bundle` read. This matters: ordinary production opens do not otherwise retain `_runtime_document`; the genuine-provider positive exercises this hydration shape. Repeated revision ambiguity, wrong/missing matching publication, history cursor loops and unavailable history refuse. A persisted exact pair narrows future lookups; it is never replaced with a later head's pair.
