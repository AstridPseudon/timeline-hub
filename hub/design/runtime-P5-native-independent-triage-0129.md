### 2. Mixed native + doc.patch preview, [fields] and [atomic]

Owning test: tests/test_timeline_commit_integration.py:502-585.

The submitted operands are valid against the authentic capture:

- The base is the exact edit.head() pair, and the test asserts the normal parent payload has no meta key.
- Command 0 is generated by the real edit.move("music-bed", 1, document=document) capture path.
- Command 1 is doc.patch with select null, version 1, root path parent/["meta"], before {"state":"absent"}, and a complete object value. Setting the missing root object is permitted by §2; no missing child ancestor is being implicitly manufactured.
- The request-level and auth-probe step reads both correctly declare parent/["meta"] as absent at the batch/step boundaries. The native move does not write meta; the later patch therefore sees the same absent state.
- Steps partition commands contiguously as [0] and [1]; the patch step’s submitted patch equals the doc.patch change. Both explicit merge modes are valid. The preview uses a separate dry-run key and the stale-head expectations distinguish fields merge from atomic scope conflict.

The observed provider failure is real. The exact final log reports HTTP 409 capture_mismatch, “submitted reads does not match authoritative capture,” at Agent commands.py:266. The concrete path is:

- Agent _commit_patch.py:287-294 captures request/step reads by calling ctx.read.
- That appends the declared read to the same record["reads"] list used for the native command recorder.
- commands.py:247-266 then compares the submitted native command’s authored reads against that augmented list and rejects it.

The approved contract says request reads are additional to provider-captured semantic reads, are inherited as dependencies, and do not assert that native captures or omitted step reads are empty (§§1, 3). Therefore the provider must keep request/step dependency capture separate from the submitted native command’s exact authored-capture comparison while still persisting the dependency union/history. Correction owner: Agent provider. Minimum fix: isolate inherited declared reads from command-level submitted-read claims in execute/CommitPatch; do not alter these test operands. This same defect affects both [fields] and [atomic]; it is not a merge-mode distinction.

There is also a test expectation that must be repaired independently. At tests/test_timeline_commit_integration.py:540, the test asserts accepted["data"]["reads"] == body["reads"]. The approved CommitAccepted schema has no reads property (contract/schemas/timeline-commit.json:965-1067), and Runtime’s accepted result construction (runtime_protocol/timeline_commit_store.py:1073-1085) does not add it. The contract requires declared request reads to be stored in the immutable history entry (§7); the current Runtime does that through _history_metadata at runtime_protocol/timeline_commit_store.py:76-90,1254-1259. Correction owner: Runtime test owner. Minimum fix: remove that out-of-contract accepted-data assertion or assert the history entry’s stored reads; retain the provider/read dependency and history assertions. This is not a reason to weaken the mixed-command behavior test.

### 3. Wrong-previous doc.patch

Owning test: tests/test_timeline_commit_integration.py:588-618.

The request is intentionally invalid and otherwise well formed: the normal base has parent/["meta"] absent, both request and step reads correctly say absent, while the patch claims a fabricated present previous value. The test does not confuse this with a stale-head conflict. Under approved commit-v2 §2, a wrong before at the original base is invalid; §4 requires HTTP 422, outer validation_error, details.status invalid, semantic code previous_value_mismatch, path, current head, hint, and suggested command, with no receipt/write.

The observed HTTP 409 conflict/refused, “patch previous value does not match,” is a provider defect, not a test defect. Agent _doc_patch.py:363-366 raises CommandError(kind="previous_value_mismatch"); Agent commit.py:396-402 hard-codes _failure to HTTP 409/refused unless a kind is placed in its conflict set, and commit.py:1109-1115 does not classify original-base previous_value_mismatch as invalid or attach structured path/hint fields. Correction owner: Agent provider. Minimum fix: map an original-base previous-value failure to HTTP 422/validation_error/details.status invalid with the structured path/hint/command, while preserving the separate replay-time mapping of a changed later-head guard to a 409 dependency conflict. Runtime’s coordinator already admits details.status values including invalid (runtime_protocol/timeline_commit_execution.py:109-114).
