## Canonical authority contract

The startup seam is the existing `astrid.sdk.timeline.commit.create_runtime_commit_service` provider loaded by the explicit `astrid` profile.  Runtime asks the provider for `project_capture(document, authoring_preview=...)`, and for working copies also for `capture_candidate_inputs(document, candidate=...)`; Runtime owns the admission comparisons and does not construct or strip a second graph.

The exact canonical projection is `{config, registry, expansion}`.  For a saved revision, `expansion` is the complete fieldset `{canonical, parent_revision_id, parent_content_digest, children, shots, occurrences, outputs, graph}` where `children` carries `(timeline_id, revision_id, config_version, config_hash)`, `shots` carries `(shot_id, revision_id, content_digest, name, text_bindings)`, `occurrences` and `outputs` are the complete projected rows, and `graph` is the complete immutable closure `{parent_revision, shot_revisions, internal_timeline_revisions}`.  For a candidate, the same common fields are compared exactly and the candidate decoration is `working_copy` (candidate/publication/base marker); candidate projection does not gain a saved `outputs`/`graph` claim.  The excluded decoration is only the old outer GET/read envelope: outer `created_at` and the duplicated parent `dependency_manifest`; authored payload fields, nested manifests, IDs, digests, pin order, occurrences, outputs, and the canonical graph are not excluded.

Runtime requires exact project/timeline scope and immutable source identity.  Saved references must resolve the named revision and matching parent digest through the retained closure, media and retained document inputs; there is no current-head fallback.  Working-copy references must match the frozen candidate/publication digests, exact saved base revision/digest, candidate scope, source placement/shot mappings, unchanged reused child bases, retained document pins, and a validated candidate closure.  The Agent provider must derive the preview from that candidate; caller labels, metadata, or a hash-only marker cannot become authority.  Runtime compares `config`, `registry`, the complete expansion, parent digest, authority expansion, and candidate marker with canonical JSON equality.

An explicit `source_kind: "cas"` is native/uncertified and never acquires a canonical source.  A working-copy claim without the complete `authoring_preview.candidate` is admitted only as CAS-only/UNCERTIFIED; if its marker contradicts the snapshot authority it is refused before admission writes.  Previously admitted captures that cannot be reverified are relabelled CAS-only per alias, without rewriting their stored bytes.  These are the settled legacy behaviors, not replacements for a positive capture.
