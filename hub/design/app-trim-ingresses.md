# App trim ingresses (static map, 2026-10-20)

**Decision.** The smallest first slice is the existing *single selected parent media clip* inspector’s discrete `Source In` / `Source Out` controls (`components/PropertiesPanel/ClipPanelBody.tsx:151-159,353-371`). On commit/blur, capture the displayed raw parent basis and submit one `clip.trim` with `args.in_s` / `args.out_s` in source seconds; omitted endpoint means “retain captured/current endpoint”. Do not route this through the generic `onChange`/rows writer. The bulk controls (`BulkClipPanelBody.tsx:258-272,694-702`) are not this slice: they fan one patch over multiple clips and need an atomic batch with per-parent captures, not one parent-only command.

**Native contract.** Agent d4743e29’s `clip.trim` (`astrid/sdk/timeline/_trim_commands.py:14-97`, tests `tests/editing_conformance/test_recipe_m2_clip_trim.py:50-86,119-189,192-218`) accepts only `parent/clip:<id>`, literal un-mapped registry media with an authenticated positive duration, and finite source endpoints inside `[0,duration]`. It preserves `at`, `track`, `asset`, `speed`, unrelated/opaque data; writes `from=source_in`, `to=source_out`, `hold=source_out-source_in` (six-decimal authored precision), and clears only supported legacy `for`/`until` intent. `hold` is source seconds; playback duration is `(to-from)/speed`, not `hold`. No occurrence, shot/group child, mapped source, params/keyframes/relations, or duration-missing fallback.

The frozen App bebfdf851 adapter is the matching port: `commands/clipTrimCapture.ts:18-40,83-240` and `commands/clipTrimGesture.ts:21-58`; the session port validates displayed head/project/timeline and exactly one literal parent (`commitSession.ts:289-345`), freezes the begin basis, creates the native preview, and queues the same command/outbox (`commitSession.test.ts:714-942`, `clipTrimGesture.test.ts:22-89`, `useTimelineCommandSession.test.tsx:355-454`). The preview is intentionally narrow (`from/to/hold`, optional existing `speed`/`app`) and `projectClipTrimPreview` is local-only; no snapshot fallback. Current integration `c8566f12` does not contain this frozen port, so implementation must port it before wiring the inspector.

**What the current gestures actually mean.** The canvas handles are emitted by `TrackListRenderer.tsx:329-335` (`data-resize-edge`, clip, row) and consumed document-wide by `useClipResizeGesture.ts:227-356`: target must be inside the timeline wrapper and a resize handle; a 4px pending threshold claims gesture owner `trim`; pointerup before threshold selects; move/up/cancel/blur are window/document listeners (there is no `setPointerCapture`). Snap reads are sibling starts/ends plus `0` (`useClipResizeGesture.helpers.ts:87-99,257-344`), threshold `8px/pixelsPerSecond`, optional shot hard end, and media source-duration bounds (`:43-84`).

| Existing ingress | Semantics from current code | `clip.trim` alone? |
|---|---|---|
| Inspector Source In/Out, one unambiguous parent | `at`/track unchanged; only source window and derived source `hold` change. | **Yes**, first slice, after discrete capture. |
| Free right-edge audio media handle | `start/at` and track fixed; `from` fixed; `to=from+duration*speed` changes (`useClipResize.ts:151-158`). | **Yes** only for this exact ungrouped parent-media case, after preserving the existing speed and converting snapped timeline end to source `out_s`. |
| Free right-edge visual media handle | `start/at` fixed, but `from/to` stay fixed and `speed=(to-from)/newTimelineDuration` changes (`useClipResize.ts:135-148`). | **No**: this is a retime, not source trim. |
| Any free left-edge media handle (audio or visual) | `at/start` moves and source `from` changes; visual also rewrites speed, audio derives a new `to` (`useClipResize.ts:135-158`). | **No**: never silently turn this into source-only trim; requires atomic move+trim (and possibly retime). |
| Hold/text/effect handle | Only timeline `hold` changes (`useClipResize.ts:131-134`); there is no source window. | **No**: use the Agent `clip.set`/hold semantics, not `clip.trim`. |
| Any pinned/group handle | `resize-math.ts:144-210` shifts preceding/following children around the boundary; `useClipResize.ts:286-340` also enforces contiguity, overlap repair, row/track patches, and per-child metadata. | **No**: requires one group/shot-owned atomic resize operation. |

`useTimelineCommandsService.trimClip` (`:707-770`) is not a substitute: it is a legacy timeline-bound trim, changes `at/from/to`, refuses pinned groups, and applies a config mutation. The existing `useClipResize` commit (`:268-377`) passes snapped **timeline** start/end through `rowsToConfig` (`timeline-data.ts:308-364`), whereas native `clip.trim` takes **source** seconds and deliberately does not frame-quantize its endpoints. The conversion used by the pointer path is `source = from + (timeline-at)*speed` (`timeline-data.ts:687-689`); frame snapping is `round(timeline*fps)/fps` (`time-grid.ts:46-69`) before that derivation. Keep these units explicit.

**Missing Agent operations before the remaining handles can migrate.** Add a captured semantic operation (or an explicitly atomic command batch with equivalent guards) for: (1) free left edge, combining placement `at` with source `from/to` and visual-rate policy; (2) visual right-edge retime, changing `speed` while retaining source bounds; (3) group/shot resize, recording membership/order and all child placement/source writes atomically; (4) occurrence-owned child resize with occurrence/shot ownership and boundary guards; and (5) bulk source trim with one command per literal parent and a grouped atomic submission. Existing `clip.move`, `clip.set`, and `clip.trim` are primitives, not proof that these compound gesture semantics are captured safely. Preserve the current passing resize tests and add command-path coverage; do not replace them with refusal expectations.

**Original test anchors to retain/extend.** `hooks/useClipResize.test.tsx:264-346,458-626` covers free media and group edge commits; `lib/resize-math.test.ts:62-213` covers edge/group shifts; `lib/time-grid-conformance.test.ts:298-363` proves snap-before-source math; `components/TimelineEditor/TimelineCanvas.test.tsx:899-931,980-1163,1172-1238,1451-1553` covers handle DOM identity, focus/gesture ownership, no-pointer-capture release, source bounds, and group handles; `hooks/useClipResizeGesture.test.tsx:72-102` covers live boundary refresh. These are behavior evidence, not authorization to reinterpret a left move as `clip.trim`.
