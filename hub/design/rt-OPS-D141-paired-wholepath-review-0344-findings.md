## D141H-SEC-001 — blocking — terminal trace append and validation are not custody-safe

This is the independent Runtime 0340 finding and is present unchanged in this
0331 App-pair candidate. `bin/test-run:107-116` stops/reaps the sampler, then
calls `d141-append-final.py`, then calls `d141-validate-trace.py`. The append
helper at `bin/d141-append-final.py:27-30` uses `Path.open("a")` without
`O_NOFOLLOW`, regular-file/owner verification, or binding to the sampler's
inode. The validator at `bin/d141-validate-trace.py:30-35` performs `lstat`
and then a separate path read.

Independent terminal probes on the actual source showed:

- Replacing the trace path with a symlink made `d141-append-final.py` return
  0 and append to the symlink target (`target_bytes=81`).
- Replacing it with a FIFO made the helper block until an external 2-second
  timeout (`rc=124`).

Therefore a swap between sampler reaping and finalization can redirect the
write, block the runner, or let validation inspect a different inode. The
required bounded refusal/no redirected writes/block and durable KEEP custody
are not met. The fix must use a securely opened descriptor with no-follow,
regular-file/owner checks, and descriptor/inode custody through final append
and validation; add a sampler-reap-to-append poison control.

## D141G-SEC-002 — blocking — `D141g-paired-control` is a production arbitrary-pair authority

The new production validator explicitly accepts the decision string
`D141g-paired-control` (`bin/d141-validate-receipt.py:176-183`) but applies no
approved suite, source, selector, or production-builder binding to it. It only
checks that the receipt's self-supplied pair hashes match rows currently read
from `tests/suites.conf` (`:212-275`). The paired controls themselves create
arbitrary control suites/commands and a fixture source, then issue that
decision (`controls/real-controls.py:334-349`); the exact author harness
accepted this pair and ran it through the installed/publication/received-bin
path.

This is outside the settled scope: no general arbitrary pair/source/command
override is allowed. A caller able to place a trusted-looking decision and
registry rows can use this production decision to admit a pair unrelated to
the approved App P2-six/P1/P3/D141j builder output. The exact App path is
hardcoded only under `D141g-next-app-journey` (`:276-305`), so it does not
constrain `D141g-paired-control`. Remove this authority from production or
bind every production decision to the approved route and genuine normal D66
registration; keep any synthetic control-only decision outside the installed
validator.
