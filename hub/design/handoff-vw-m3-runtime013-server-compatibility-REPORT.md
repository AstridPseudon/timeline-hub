- Runtime contract metadata and `timeline-commit-bundle.json`.

`contract/artifacts.json` verifies all 75 current artifact bytes, including the
schema and generated clients. The only contract-side source change after the
producer is the compatibility-proof generator helper; it does not alter the
published schema or generated bytes.

There are intentional semantic migration guards, which must remain separate
from wire compatibility:

- old timeline-document creation/read/CAS writes return `410 retired_route`
  and point to canonical publication/inspection;
- legacy timeline writes return `410 retired_route` with
  `reason=timeline_commit_required`;
- tracked legacy parent publication/render refuses with `409` and
  `reason=timeline_commit_required`;
- historical flat-projection timeline recovery returns `410` with
  `reason=timeline_restore_required`.

These are expected refusals of retired writers, not changed request/response
schemas. A caller that still expects those legacy operations to succeed is not
behaviorally compatible and must migrate to `commitTimeline`/`timeline.restore`;
the normal canonical client path has no identified wire mismatch. The current
server source must therefore be frozen as `8f105c26`, not compared for equality
with the client producer SHA.

and artifact identity with compatible server patch `81f8c7e0` in
`scratchpad/orch/design/runtime-current-tuple.md:35-53`; this report extends
