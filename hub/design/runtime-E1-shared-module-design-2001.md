## Exact module, API and dependency direction

The module contains six functions, no stateful object, new exception class, DTO, schema loader, IO, result cache, history cache, or authorization callback. Its data is the existing finite JSON and existing physical-image mappings. It may import standard-library `hashlib`, `math`, and `json`; deterministic serialization uses exactly Runtime's current canonical spelling. Existing caller validation and exception translation stay in place.

| Proposed function | Current implementation selected | Exact meaning and caller integration |

Runtime producer/auth continue using this binding. Agent command-state imports `value_equal as equal`; downstream recorder, inverse and patch imports retain their public name. Do not replace emitter `_same`: serialized equality has a different boundary. |

C0 permits only finite JSON, so use the Runtime version at validated commit boundaries; before deleting Agent's helper, prove its actual external callers cannot rely on nonfinite/subclass behavior. If such a supported caller exists, hold that extraction and recalculate the deletion budget. Do not silently broaden or tighten a public domain to make E1 fit. Runtime's image schema prevents the field/prefix mismatch between the two current root candidate implementations; retain malformed-image refusal before the shared lookup.

Packaging: proposed next Runtime release `astrid-runtime 0.1.1` includes this module through the existing `runtime_protocol*` setuptools package discovery. Existing Runtime `0.1.0` lacks this API. Do not vendor it into `astrid_runtime_client`, create another distribution, discover a sibling checkout through `sys.path`, or fall back to an old copy. Preserve module/name imports with import aliases in existing files, not wrapper functions. No package install, version edit, lock/pin change, acquisition or package build is performed by this design task.

Direction: **Agent → Runtime pure module**. Runtime never imports Agent to obtain a rule. Runtime's existing provider call remains its explicit execution ABI, not a Python package dependency on Agent. The pure module must not import `service`, `store`, `timeline_commit_port`, producer custody, or Agent; this also removes the current equality helper's dependency on the producer module's port imports for callers that only need equality. The installed Agent now intentionally requires the small Runtime distribution for these paths; document the change from `bundle_from_document`'s current “without a Runtime dependency” claim when implementation lands.
